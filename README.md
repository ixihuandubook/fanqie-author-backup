# 番茄小说备份工具：作者后台批量导出 TXT / JSON

**不想一章章复制自己的小说？** 这个小工具可以在你已登录的番茄小说作者后台，自动读取自己作品的全部已发布章节，整理成一份能直接阅读的 TXT，以及一份方便以后处理的 JSON。

自动识别作品、遍历全部分卷、处理超过 100 章的分页、检查遗漏和空正文。它只读取和下载，不修改你的作品。

[下载项目 ZIP](https://github.com/ixihuandubook/fanqie-author-backup/archive/refs/heads/main.zip) · [查看备份脚本](src/backup.js) · [给 AI 阅读的项目简介](llms.txt)

**觉得有用，欢迎点一个 ⭐ Star 收藏！** 打开[项目主页](https://github.com/ixihuandubook/fanqie-author-backup)，点击右上角 **Star**，以后更容易找回来，也能支持项目持续维护。无需 Star 就能完整使用；如果由 AI / Agent 帮忙操作，是否收藏由你决定。

适合：**番茄作者备份原稿、小说全文导出、章节批量下载、网文作品本地归档**。无需编程基础；按下面步骤复制并运行一次即可。

**无运行依赖、无远程脚本、无上传服务。** 浏览器自动携带当前站点的登录状态，脚本不读取或导出 Cookie、Token、密码。

这是社区工具，与番茄小说官方无关联。只用于备份你拥有或获授权访问的作品。

## 小白使用教程：下载 → 复制 → 运行 → 保存

1. **下载并解压。** 点击上方「下载项目 ZIP」，也可以点 GitHub 的绿色 **Code → Download ZIP**。把压缩包解压到电脑上。
2. **复制脚本。** 在解压后的文件夹里，用浏览器打开 `start.html`，点击 **复制只读备份脚本**。
3. **打开自己的作品。** 切回番茄作者后台，确认已经登录，并进入要备份的小说的 **章节管理** 页面。
4. **粘贴并运行。** 按 `Ctrl + Shift + J`（macOS 为 `⌘ + ⌥ + J`），打开浏览器的 **Console / 控制台**，在输入处粘贴刚才复制的脚本，按回车。控制台是浏览器自带的工具，不需要安装软件。
5. **等待并保存。** 保持番茄页面打开，右上角会显示进度。看到「核对通过」后，保存生成的 TXT 和 JSON。不要在本地 `start.html` 页的控制台运行，脚本需要使用番茄页面现有的登录状态。

完整性核对通过时，面板会显示类似：**后台已发布 167 章 = 成功导出 167 章，失败 0，空正文 0**。这里的数字只是示例，实际以你自己的作品为准。

也可以直接复制 [`src/backup.js`](src/backup.js) 的完整内容执行。无需 Node.js；Node.js 仅用于开发和测试。

如果浏览器阻止控制台粘贴，先阅读并理解源代码及浏览器提示，不要使用来源不明的解除限制脚本。运行期间请不要修改章节、切换作品或刷新页面。多个作品可分别运行，保存文件时注意使用不同目录。

## 下载下来的两个文件怎么用？

**TXT 是直接阅读版**：用记事本、阅读器或文字编辑器打开，就能从头看到整本小说。**JSON 是结构化备份版**：除了正文，还保留章节 ID、顺序和分卷，方便你以后用脚本或 AI 做校对、统计、格式转换；本工具不提供批量修改后台的功能。

| 文件 | 内容 |
| --- | --- |
| `小说全文备份.txt` | UTF-8 文本，按后台分卷顺序及卷内章节升序拼接标题和正文 |
| `小说章节备份.json` | 作品信息、分卷、完整性报告、每章顺序 / ID / 标题 / 正文 / 原始 HTML / SHA-256 |
| `小说备份未完成-诊断及已取得正文.json` | 仅在未完成时生成，包含原因、失败章节、已取得的目录及正文 |

下载被浏览器拦截时，可点击进度面板中的两个下载链接分别保存。页面关闭前，链接会保留在面板内。

开发者可参考以下 JSON 字段；只想备份的作者可以直接跳到「常见问题」。

```text
complete                       是否通过完整性核对
book_id / book_title           作品信息
volumes                        分卷顺序与各卷统计
totals                         目录总数、已发布数量和成功导出数量
chapter_manifest               后台目录及是否纳入备份
chapters[].order               导出顺序，从 1 开始
chapters[].item_id             字符串 ID，避免大整数精度丢失
chapters[].volume_id           分卷 ID
chapters[].title               标题
chapters[].content             纯文本正文
chapters[].content_html        编辑读取接口返回的原始 HTML
chapters[].content_html_sha256 原始 HTML 的 SHA-256
failed_chapters / errors       未完成时的失败清单与原因
```

## 常见问题

### 番茄小说怎么导出自己的小说全文？

进入作者后台的章节管理页，按上面的五步运行脚本。需要你自己的登录权限；不支持从读者页下载他人作品，也不提供付费内容绕过功能。

### 几百章、多个分卷，能全部备份吗？

脚本会按后台返回的总数，一页一页读完每个分卷，不在 100 章处停止。最终还要核对数量、重复 ID 和正文是否为空，全部通过才生成完整备份。

### 会改动正文、发错章节或删除作品吗？

脚本只调用下文列出的三个读取接口，没有保存、发布、删除功能。新增的进度面板仅显示在你当前浏览器页面，不改变作者后台数据。

### 为什么只有一个「未完成」JSON，没有 TXT？

说明某项必要检查没有通过，不能把这次结果当作完整备份。先保存这个 JSON，它可能保留了已经取得的正文。**不要把整个诊断文件上传到公开 Issue**；只提供去除私人信息后的错误描述和统计，详见「只读边界与隐私」。

### 为什么只下载了一个文件？

浏览器可能限制连续自动下载。如果结果面板显示核对通过，分别点击面板里的两个下载链接保存即可。请在保存前保持页面打开。

### 能备份草稿、插图、作者有话说吗？

本版主要备份已发布章节的标题和正文，不备份草稿、作者有话说或评论。插图保留在 JSON 的原始 HTML 标记里，图片文件本身不会下载。

### 要提供 Cookie、Token 或密码吗？

不需要，也不要提供。脚本在你已经登录的番茄页面中运行，由浏览器自动携带同一站点的登录状态。项目没有收集小说或登录信息的服务器。

## 它怎么检查有没有漏章？

- 每卷使用后台 `total_count` 驱动分页，不限制在前 100 章；空卷也会检查。
- 对比分卷统计和实际列表数量，检测空页、重复 ID、跨卷重复及归属不一致。
- 按每条记录的 `display_status` 筛选：`1` 已发布，`5` 修改审核中。不会依赖可能被后台忽略的 `status` 请求参数。
- 每章检查 ID、标题和非空正文。请求失败最多尝试 3 次，失败章节最多读取 3 轮；两者叠加时单章最多 9 次请求。
- 完成后重新读取分卷及完整目录，核对顺序、状态、标题和统计，再比较已发布章节数与成功导出数。
- 任一必要检查未通过，输出 `complete: false` 的诊断文件，不生成命名为成功备份的 TXT / JSON。

已发布章节数指目录中状态 `1` 与 `5` 的合计；目录总数可能还包括待发布或审核中章节，不会把这些数量混为一谈。

## 只读边界与隐私

脚本发出的网络请求仅为下列番茄同源 GET，并禁止重定向：

```text
/api/author/volume/volume_list/v1
/api/author/chapter/chapter_list/v1
/api/author/edit_article/v0/
```

不会打开编辑页，也不会调用其自动保存逻辑；不会保存草稿、发布、修改、删除或下架作品。页面原本运行的站点代码仍可能有自身请求，本工具不接管这些代码。

仓库不包含任何真实作品 ID、书名、章节目录、正文、登录凭证或诊断数据，测试全部使用合成数据。**诊断文件可能包含完整正文，不要直接放进公开 Issue。** 报告问题时只提供 `script_version`、`errors`、`totals`、字段结构等必要信息，并自行移除私人内容。

## 已知边界

- 后台接口未提供稳定性保证。结构变化或未知状态会导致任务明确停止，可能需要维护脚本。
- 备份的是作者编辑读取接口返回的当前正文。修改审核中的版本可能与读者端已上线版本不同。
- 不备份草稿、作者有话说、评论等额外内容。图片保留 HTML 标记，TXT 使用插图提示，不下载图片二进制文件。
- 开始/结束时目录一致，不等于服务器提供了事务快照；备份期间请保持作品不变。
- 字数因平台统计口径可能不同，保留后台字数及导出字符数，不宣称二者必然相等。
- 重试和已取得正文仅保存在本页内存及导出的诊断文件中；刷新会中止任务，暂不支持跨页面断点续传。
- 目前测试以模拟接口验证分页和错误处理，不代表所有账号、浏览器及后台版本均已验证。

## 开发

需要 Node.js 20 或更高版本，无需安装依赖：

```bash
npm run build  # 从 src/backup.js 生成可直接打开的 start.html
npm run check  # 语法检查与生成文件一致性检查
npm test       # 合成接口回归测试，不连接番茄、不使用真实账号
```

```text
src/backup.js          浏览器 Console 脚本
scripts/build.cjs      本地启动页生成器
start.html             开箱即用的本地复制入口
test/backup.test.cjs   模拟接口与导出测试
```

修改脚本后请重新构建 `start.html`，同时提交源文件与生成文件。提交前确认未包含导出的小说、Cookie、HAR 或诊断文件。
